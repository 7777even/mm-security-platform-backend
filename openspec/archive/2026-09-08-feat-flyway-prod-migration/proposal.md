# Proposal: 生产库在线迁移引入 Flyway

## 为什么（Why）

- 后端长期技术债 P3：生产库在线迁移一直**未引入 Flyway / Liquibase**，`fac_workstation`、`fac_audit_log` 等表此前仅 dev 用 `schema.sql` 全量重建，生产无版本化迁移能力（见 retro `2026-09-07-dashboard-realtime-cleanup.md` / `2026-09-07-alarm-fields-align.md`）。
- 生产库选型已决策为**达梦 DM8**（信创国产化，设计稿意图）；`application-prod.yml` 的 PostgreSQL 降为兼容/回退 profile。
- dev(H2) 当前靠 `spring.sql.init` 加载 `schema.sql`/`data.sql`，机制与生产的 Flyway 不一致，且 `db/schema-h2.sql` 已分叉（缺告警新列）。

## 目标（What）

1. 引入 **Flyway 9.22.3**（`spring-boot-starter-flyway` 托管版本，`flyway-core` 内置 H2 + PostgreSQL 支持），`spring.sql.init.enabled=false` 由 Flyway 统一接管建表。
2. 三套方言版本化迁移：
   - `db/migration/h2/`：V1 全量快照 + V2 种子（dev，可本地实跑验证）。
   - `db/migration/postgresql/`：V1 + V2（PG 方言，兼容/回退）。
   - `db/migration/dameng/`：V1 + V2（DM8 Oracle 兼容方言，信创生产选定，**须到达梦实例复核**）。
3. 按 profile 指定 `spring.flyway.locations`：dev→h2、prod→postgresql、dm→dameng。
4. 新增 `application-dm.yml`（达梦数据源 + 安全基线 + Flyway 位置），并在 pom 的 `dm` profile 内声明 `DmJdbcDriver18`（仅 dm 激活时解析，不破坏 dev 构建），驱动经 `mvn install:install-file` 本地安装。
5. 移除被取代的 `schema.sql` / `data.sql` / `db/schema-h2.sql`，更新 README / docs / AGENTS 的 Flyway 双轨说明。

## 非目标（Out of Scope）

- 不在本次为达梦实例实跑验证（无实例、无驱动）；仅提供经评审的 DM8 方言迁移与兼容缺口说明。
- 不接入 Liquibase（与既有约定二选一，选 Flyway）。
- 不为既有生产库做存量数据迁移/回填（属后续独立变更，须单列 proposal + 回退方案）。

## 风险

- **Flyway 社区版无官方达梦 database 模块**：达梦迁移 SQL 在本地无法由 Flyway 实跑校验；若上环境 Flyway 报 `Unsupported Database`，需引入达梦兼容的 Flyway database 插件或将数据库探测配为兼容模式（已在 `application-dm.yml` 注释标注）。
- 达梦方言与 H2/PG 存在类型差异（如 BOOLEAN 标志位在 DM 用 `NUMBER(1)`、自增主键用 `GENERATED BY DEFAULT AS IDENTITY`），三库列语义一致、底层类型不同，须在达梦实例复核。
