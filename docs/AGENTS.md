# AGENTS.md — 文档目录职责（后端）

本仓库有三类"写东西的地方"，职责不重叠。放错地方的知识等于丢掉。

| 目录           | 回答的问题           | 内容特征                             |
| -------------- | -------------------- | ------------------------------------ |
| `docs/`        | 系统**现在**是什么样 | 长期共识，跨版本有效，改了要同步代码 |
| `openspec/`    | 系统**将要**怎么变   | 唯一业务规格来源，含 change 与 specs |
| `engineering/` | 这次**做得怎么样**   | 短期过程记录：计划、QA、复盘         |

**短期开发记录放 `engineering/`，不放 `docs/`。** QA 结果、发布检查、复盘不写进 `docs/`。

## docs/ 现有内容

| 路径                       | 说明                                                                 |
| -------------------------- | -------------------------------------------------------------------- |
| `api/README.md`            | 跨库契约同步纪律 + Controller ↔ 契约域映射；**契约真源在前端库**      |
| `architecture/README.md`   | 分层职责、安全过滤器链、数据层与迁移、环境与运行基线                  |

## 改完代码后的四查

功能完成后必须检查并同步：

1. **契约是否更新**——接口字段、错误码、权限码变化是否同步到前端库 `docs/api/*.openapi.json` 与调用方。
2. **结构是否变化**——表 / 字段 / 索引 / 约束变更是否同步 `schema.sql` 快照与 `resources/db/` 增量 SQL。
3. **安全是否越界**——零下行控制、签名、鉴权白名单、密钥注入方式是否被绕过。
4. **运行是否变化**——端口、profile、环境变量、启动脚本、部署配置是否受影响。

前三者落在 `docs/`（长期共识）；本次验证的过程与证据落在 `engineering/qa/`。
