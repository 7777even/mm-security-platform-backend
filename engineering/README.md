# engineering/ — 研发过程记录（后端）

存放**短期、一次性**的研发过程记录，与长期知识库 `docs/` 严格分离。文件命名统一 `YYYY-MM-DD-<kebab-slug>.md`。

## 三个子目录

| 目录     | 记什么                                                                     | 何时写                   |
| -------- | -------------------------------------------------------------------------- | ------------------------ |
| `plans/` | 推进计划、里程碑台账、阶段性排期                                           | 排期确定或调整时         |
| `qa/`    | 验证过程与结果：范围、验收口径、实际命令与用例数、未运行项、结论、证据附件 | L3 / L4 交付前必写       |
| `retro/` | 复盘：做得好、问题、原因、改进方案                                         | L3 / L4 收尾、故障复盘时 |

L0 / L1 / L2 改动默认不写这些记录。

## 四条纪律

1. **不写第二套任务**：目录里只记状态和证据，实施任务永远以 `openspec/changes/<name>/tasks.md` 为准，不得在本目录另立任务清单。
2. **报告实际执行的命令**：写清跑了什么（`./mvnw test` / `smoke-test.ps1` / `check-api-contract.mjs`）、通过多少、哪些没跑（例如 Docker 不可用导致 IT 未执行）。禁止用无关的全量命令冒充目标验证，禁止把未执行写成通过。
3. **证据附得上**：接口类改动附 curl / 冒烟终端输出快照；跨库契约改动附前端契约文件同步记录。
4. **临时产物不放这里**：构建日志、`target/` 产物、diff 快照等一次性文件用完即删，不入库（提交规范见根 `AGENTS.md` §6.5）。
